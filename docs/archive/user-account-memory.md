# 使用者账号与私有咨询记忆

目标（用户已确认调整）：使用者自行注册用户名，使用者只输入已存在用户名登录；不存在者拒绝。再次登录（包括另一电脑）查看该用户名的咨询历史、牌面、解读和后续对话。访客继续使用，开发者登录保持独立。没有密码验证，知道用户名即可查看其历史，此限制用户明确接受，登录入口须说明。

方案：用户名由使用者注册接口创建，随机会话 HttpOnly Cookie；在本机私有数据目录持久保存账户及每账户最多 50 条记录。历史 API 从会话确定主人，不接受客户端指定其他用户；附带当前档案 ID 校验避免切换时旧保存写入新档案。登录设置同源检查、请求大小限制和登录限速。公网代理仅放行用户登录/历史路由和用户会话 Cookie，仍剥离开发者会话。

客户端：首页及历史页新增注册/登录入口，登录后同步本人历史，退出清除账号历史和当前咨询。旧游客历史留在本机，不自动上传，不保留旧多用户切换作为账号入口。账户记忆用于历史回顾和明确选择的后续咨询，不自动把所有历史送给 AI。

验收：A/B 注册登录及大小写与重复用户名检查、重登恢复、跨账号读取/删除拒绝、伪造身份拒绝、退出后不可读；公网登录 Cookie 正常而开发者仍不可达；保存/删除/追问正确同步；类型检查和相关测试通过。服务器数据仅存在本机，电脑须在线；暂不提供邮箱验证和找回密码。

执行计划：1. 账号会话与私有历史接口及隔离测试；2. 登录页和历史同步、退出清理；3. 公网代理用户会话及隔离回归；4. 实例验证、文档和归档。采用当前任务单代理顺序实施。

验收完成：最终全量56个文件387项测试通过；类型及相关代码检查通过；生产构建通过。公网实际HTTP验证注册、英文大小写登录、重复和不存在用户名拒绝、历史重登恢复、档案写入隔离、退出和开发者屏蔽通过。诊断历史已清空。系统试用真实返回HTTP 200、usingSystemKey=true和complete=true。未验证实体浏览器逐按钮视觉操作；用户名无密码的已接受限制保持。
