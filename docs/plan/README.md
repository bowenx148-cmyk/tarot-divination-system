# 计划与待办（`plan/`）

> **本目录 = 全部尚未完成的事项**：在飞的、暂缓的、远期的，一个事项一个文件。
> **目录为空 = 没有未完成的事**（本文件只是让空目录在 git 里存在，不是一个待办）。
>
> 每份规格都要写清 **验收标准 + 技术方案 + 测试计划**——目标是**打开就能开工**，
> 而不是一句"待办 xxx"。
>
> **待办只住在这里。** 其他文档要提某个待办，只放指针（"见 `plan/xxx.md`"），
> 不得只写一行字——一行字没有验收标准，且会散落多处、互相漂移。
>
> **已经"接受、不打算改"的限制不在这里**，它们留在
> [`../OPERATIONS.md`](../OPERATIONS.md) 的「已知限制与风险」——别把接受了的限制写成假待办。
>
> 条目**完成并归档后**，才在 [`../SPEC.md`](../SPEC.md) 补一行，本文件随之删除、移入 `../archive/`。
>
> 规则见 [`../README.md`](../README.md)；条目状态与决策记录见 [`../SPEC.md`](../SPEC.md)。
