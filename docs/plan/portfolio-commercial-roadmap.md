# 求职展示与商业验证（建议路线，未授权执行发布和收费）

用户请求规划，本文是建议方案而非已实施功能。原项目CC BY-NC商业限制、免密码账号、浏览器设备限制和本机公网运行的现状，以调研报告和OPERATIONS为依据。

## 第一阶段：面试材料

方案：原项目署名、新增功能清单、数据流图、三分钟录屏、固定合成问题的真实模型输出及人工点评；不公开用户历史。验收：能说明二次开发边界、结构化检索与模型输入、SSE、资料快照、并发试用和安全局限，所报指标能由日志复现。测试：本地启动到历史恢复的演示，核查每个简历数字有证据。建议1周内完成，时间是规划而非承诺。

## 第二阶段：公开演示或开源

方案：先取得素材权属清单；秘密、用户数据与部署信息从可公开包及历史中检查；保留上游署名和适用许可证，禁止擅自把继承代码改MIT。验收：明确所有代码、卡图、音效、知识条目的出处和许可；独立环境可安装与演示，个人数据不随包发送。测试：新目录安装、配置和回归，追踪文件及git历史扫描、公开演示权限测试。实际push/建仓需用户明确指示。

## 第三阶段：是否商业化

方案A取得上游书面商业许可；方案B重新实施权属明确的商业代码和素材。账号升级为可验证身份、持久存储和恢复/删除能力；网站迁到适当托管；确认销售类目、服务条款、退款与支付资格。验收：商业许可及支付资格可核实，账号越权与支付回调不能重复发放权益，删除与备份流程可操作。测试：登录/越权、安全边界、重复回调、失败退款、备份恢复和预算限额。这里只规划，不接入收款。

## 第四阶段：小规模需求验证

建议找10到20名自愿、明确知晓AI性质的试用者，收集体验而非命中率。方案：同一测试口径记录完成率、是否理解判断依据、自然表达评分、愿付费理由和投诉；试验价与真实收费分开，未经授权先不收款。验收：有匿名原始反馈和分母，能解释退出原因；至少有人因具体价值而非恐吓愿意购买，单次成本可核算。测试：去重、事件漏报、断线与重试，核对费用日志。若主要反馈只是新奇、无人愿付费，暂停扩广告预算，先调整交付。

海外试验另核对语言质量、销售及收款地区规则。Etsy的一次交付政策不可作为出售SaaS订阅的依据；不虚报经营主体或业务类型，不替用户开店发帖。
