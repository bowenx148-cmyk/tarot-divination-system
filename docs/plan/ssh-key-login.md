# 待办：启用 SSH 密钥登录

- **类别**: 运维安全（卫生项）
- **状态**: ⏸ 暂缓（2026-09-16 决定，**非当前优先级**）
- **来源**: 原 `OPERATIONS.md` §三 一行

## 问题描述

服务器 SSH 仍使用**密码登录**。密码可被暴力破解、可被肩窥、会出现在任何记录了它的地方；
密钥登录则不可暴力破解。

**为什么之前没做**：这项与「Redis 强口令」同属**"改错即失联"**类操作——SSH 配错的直接后果是
**再也连不上服务器**。当时的判断是非当前优先级。

## 目标

SSH 只接受密钥登录，禁用密码认证；**且过程中不断开现有会话**（避免把自己锁在外面）。

## 验收标准

- [ ] 本地（或负责人指定的机器）能用密钥免密登录：`ssh root@<SERVER_IP>` 直接进入
- [ ] `sshd_config` 中 `PasswordAuthentication no`、`PubkeyAuthentication yes`
- [ ] **新开一个会话验证成功之后**，才关闭旧会话
- [ ] 禁用密码后再次新开会话，确认仍能登录（这一步是真正的验收）
- [ ] 保留一条退路：腾讯云控制台的「自动化助手（TAT）」可用（它不走 SSH，
      2026-09 迁移时就是靠它完成服务器操作的）——**这是本次操作的安全网，动手前先确认它可用**

## 技术方案

1. **先确认退路**：腾讯云控制台 → 自动化助手（TAT）能对实例下发命令。
   这是"改错即失联"类操作的**前提**，没有它就等于在赌。
2. 本地生成密钥（若无）：`ssh-keygen -t ed25519`
3. 公钥写入服务器 `~/.ssh/authorized_keys`（权限 600，`.ssh` 700）
4. **保持当前会话不断**，新开一个终端验证密钥登录成功
5. 验证通过后，才改 `/etc/ssh/sshd_config`：
   ```
   PubkeyAuthentication yes
   PasswordAuthentication no
   ```
6. `sshd -t` 校验配置语法 → `systemctl reload sshd`（**reload 不断连接**，不要 restart）
7. 再新开一个会话确认可登录

## 风险与假设

- **风险（高）**：配置错误会导致**彻底失联**。缓解手段有三层——
  ① 用 `reload` 而非 `restart`；② 新会话验证通过前不关旧会话；③ TAT 作为兜底通道。
- **假设**：TAT 在禁用密码登录后仍可用（它不经 SSH，走的是云厂商 agent 通道）。
  **动手前先实测这一点**。
