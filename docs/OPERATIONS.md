### 条目过程与理由

**N1 监控告警配置** —— 为什么刻意不自建 Uptime Kuma：监控与被监控同机，机器一挂两者同时失效，
自建等于没有监控。

**N2 `/api/health`** —— 为什么需要它：Redis 配了却连不上时，配额/试用/限流会整套**静默降级为内存实现**，
而站点首页仍返回 200、看起来一切正常——纯页面探测发现不了这种故障。该端点在此时返回 503，
成为唯一能探到该状态的信号。

**N3 来源审计** —— 决策过程：在"记明细"与"只记聚合"之间选了后者，理由是本站无需用户级追踪，
明细带来的隐私成本换不来对等的运维价值。

**N4 AOF 持久化** —— 实测记录：重启前 `quota:count` = 4、`trial:*` 键 10 个、`appendonly yes`；
控制台重启服务器后两者**原样保留**、站点正常 → 持久化生效。

**N6 依赖审计** —— 过程：`npm audit` 报 15 项（1 critical / 10 high）→ 升级 `next` 16.1.6 → 16.3.5
+ `npm audit fix` → 0 漏洞。可选 CI 经评估不加。

**N7 分支处置** —— `feature/less-modules` 的方向被决策 D4/O2 取代而废弃；
`feat/tencent-migration` 已并入 main。

**N9 Redis 故障静默降级** —— 问题：Redis 挂掉时配额/试用/限流失效，站点仍 200，且当时是空 error
handler → 无人知晓。**修法的选择**：用**外部探测**（`/api/health` 监控）而非应用内告警——
应用内告警在"应用本身没挂但依赖挂了"时同样容易漏，探测才是从用户视角出发的。

**N10 443 丢包黑洞** —— **症状**：部分访客完全打不开站点、卡在超时页；请求到不了 nginx，
监控全绿也发现不了。**根因**：Chrome 的 HTTPS Upgrades 把 `http://` 升级到 `https://`，
而本机 443 被防火墙**丢包**（`Connection timed out`）——"失败"变成"等待"，回落逻辑等不到信号。
**修复**：放行 443 → 无监听者、内核直接回 RST → 变成**快速拒绝**，浏览器得以回落。
**两个坑**：① 改「防火墙**模板**」不会同步到实例，必须直接改实例防火墙——曾因此把 22/80 一起弄丢、
致全站 502；② 本机 Clash 会把 443 扭曲成 `ERR_CONNECTION_CLOSED`，验证时须关 Clash。
**教训**：此类故障（请求到不了 nginx）监控全绿也发现不了，只能靠真机实测。

**N11 部署改 git** —— **动机**：旧 tar 流程推导出三个额外复杂度（镜像 curl / 手工对账残留 /
手工锚点），三者**全部源于用 tar 而非 git**。**切换前的服务器清点**（`comm` 三方对比）：
无 tar 残留；仓库外文件仅 `.env.local`（`.gitignore` 保护）、`.deployed-sha`、`next-env.d.ts`
三个 → 结论是**不需要 `git clean`**，原地 `git init` 即可。**镜像连通性实测**：走 `ghfast.top`
clone 成功（236 objects / 29.44 MiB / 4.59 MiB/s）。
完整 spec（验收标准、两轮真机部署暴露的两个缺陷与修复）见 [`archive/n11-git-deploy.md`](./archive/n11-git-deploy.md)。

## 三、已知限制与风险（未解决）

- **无 HTTPS**（已决策接受）：公网 IP 直连只能用 HTTP，无法绑标准证书。除观感外有实质影响——
  用户自填的 DeepSeek Key、问题内容、`ADMIN_TOKEN` 均明文过网。如需 HTTPS：加域名 + ICP 备案 + 证书，
  现有前置 Nginx 直接加 443 server 块即可，**应用侧零改动**。
- **HTTP 下 Web Crypto 受限**（同上，接受）：`crypto.subtle` 在非安全上下文不可用，API Key「记住」
  功能失效（刷新丢 Key），**上 HTTPS 才能恢复**。该限制在 UI 上已如实呈现（O6）：
  不可用时「记住 Key」整行不渲染，不出现"勾了却不生效"。
- **安全基线**：自建 Redis 只监听本机 + `requirepass` + AOF；服务器放行 22 / 80 / **443**
  （**443 必须放行**，见 N10）；`.env.local` 权限 600。
- **无调用日志**：出问题无法回溯「谁在什么时候用了什么」，只能看到计数（排查手段见[归档 §14.1](./archive/migration-2026-09.md)）。
- **公网 IP 持续被扫描**：错误日志中可见探测 Next.js Server Action 的请求（`Failed to find Server
  Action "x"`）。本项目**不使用 Server Actions**，Next 正确拒绝，**无实际影响**——属公网 IP 的
  正常背景噪音，也是及时升级依赖的理由之一。

## 2026-10-09 本地运行与分享边界

已接受的本机形态：单开发者随机会话令牌，系统配置为本机文件，适用于单进程；没有多实例会话/配置协调。密码按用户指定保留，公网经白名单代理拒绝所有管理入口。只允许本机管理是网络入口的限制，不是根据用户填入的IP判断。

分享使用独立生产构建和ngrok账号域名；ngrok负责连接重试，启动脚本不做进程崩溃后的自动重启。游客历史按域名保存，迁移域名时需要保留旧站点数据。第三方中转是请求内容的处理方；流量检查已关闭。原内存限流不能跨重启持久，当前另外使用下述持久化试用账本；公网保守地共享一个IP额度。

沟通优化来自公开NVC与动机式访谈资料及humanizer表达规则，未导入受版权保护的整本书；无真实案例验证，不能宣称心理疗效或保证占卜准确。

### 用户名档案

开发者发布配置：新部署没有固定用户名或密码，首次初始化需私有DEVELOPER_USERNAME与至少12字符的DEVELOPER_PASSWORD；已有auth.json的哈希与加密秘密不重置。本机用户名已转入忽略的环境文件，原本机凭据继续有效；公开副本不携带该文件。

用户名登录没有密码校验，知道用户名即能查看历史，用户已明确接受。账号及最多50条咨询存在 .local/user-memory.json，须与其他 .local 配置一起私有备份；删除该文件会丢失账号和历史。账号历史不保存到浏览器 localStorage，退出后清除当前账号缓存。账号会话30天；游客记录留在原浏览器。公网仅转发 tarot-user 会话，开发者会话仍被剥离。当前 .local 文件持久化适用于单机运行，开发和生产并行修改同一文件时存在并发覆盖风险。

### 知识及试用持久化

.local/knowledge-library.json 保存开发者参考条目；默认包含用户须知、公开沟通原则和24条教学摘要，不包含完整心理学书籍。已有私有文件不自动覆盖；本机此次已追加教学资料。结果中保存资料快照，后续编辑不改旧记录。

.local/trial-ledger.json 保存哈希设备注册、设备/账号已用试用、临时占用以及按上海日期的每日系统次数。账本通过独占 .local/trial-ledger.lock 同步事务；占用10分钟后过期。正常重启保留用量；异常进程终止可能遗留lock，须确认全部相关服务已停止后再清除这个锁文件，不能删除账本。原试用缓存/Redis限流之外，持久账本是额外硬限额，原配额开关不会绕过此硬限额。免费次数在上游成功开始生成时消耗，流式中断不保证退款。设备标识不是实体硬件标识，依然可绕过。
### 抽牌音效与教学资料补充

本机私有知识库追加24条教学资料，原条目保留；更新备份在 `.local/knowledge-before-night.json`。通用部署已有知识库不会自动覆盖，导入 `lib/knowledge/teaching-notes.json` 时留意重复ID。正文来源标记由模型生成，完整参考快照才是实际请求记录。

音效使用Web Audio合成，默认静音；不支持或解锁失败时降级为无声抽牌。设置保存于浏览器`tarot-draw-preferences`，受系统减少动画偏好约束。验证使用Edge桌面与390px移动视口模拟，未验证实体手机扬声器/Safari和主观音色；正常关机后公网暂停，启动见 reports/operations/START-AFTER-SHUTDOWN.md。
