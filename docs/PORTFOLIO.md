# 作品展示与面试说明

本文负责演示路线和可解释的工程贡献。实际质量门禁数字以SPEC和发布检查报告为准，不虚报在线用户、准确率或并发量。

## 三分钟演示

输入学业/感情/收入问题 → 选择时间之流并查看三个牌位 → 点选一张，切换报数完成剩余牌 → 使用个人Key生成 → 展开本次参考依据 → 保存到自己注册的测试用户名 → 退出再登录恢复历史。演示用户名与问题应为合成，不展示真实用户内容、Key或后台私人配置。每次真实生成会收费；没有Key时可演示到抽牌和资料管理，说明AI调用尚未运行。

截图见reports/FOREST-THEME-2026-10-13.md。在localhost使用本机后台编辑一个带领域与牌面条件的测试知识条目，显示停用前后检索差异；不要通过公网展示后台Key。

## 面试能展开的内容

| 问题 | 应解释的实现与边界 |
|---|---|
| 为什么不用向量数据库？ | 78张牌的ID、方向和牌位明确，用结构化筛选/评分先满足当前规模；不是已完成向量RAG |
| 资料如何影响回答？ | retrieveKnowledge匹配条目与领域牌义、限制内容总量、附入prompt并保存参考快照；提供资料不证明忠实采用 |
| 流式输出如何可靠？ | ReadableStream、TextDecoder和SSE分块解析；网络块不是完整消息，区分完成、错误和断线 |
| 抽牌如何一致？ | Fisher–Yates洗牌、同局保留牌堆与顺序，点选/报数共享状态，已选牌不重复 |
| 试用如何控制？ | 设备/账号联合标记、文件锁预占和释放、每日硬限额；浏览器ID不是硬件身份 |
| 为什么还不能生产多人运营？ | 用户名无密码、JSON数据与会话不具备多实例事务；管理隔离依赖代理，网站依赖本机在线 |

简历表述：“基于开源indigo-tarot二次开发，扩展结构化知识检索与参考快照、流式咨询、用户名历史及持久试用控制，完善牌阵教学与两种抽牌交互。”仅对本人能独立解释、修改和验证的部分写“负责实现”；坦诚使用AI辅助工具。

## 回答质量比较方法

固定相同问题、牌组、方向、牌位、模型和参数，分别提供/不提供参考资料，每组保留原始回答、输入token、输出token、耗时及模型版本。以直接回答、牌位覆盖、资料忠实、事实边界、行动具体性作人工评审，打乱顺序并记录评审者。问题使用合成场景；不能因为出现一个来源标题就认定质量提高。

已有模型样本见reports/REAL-MODEL-SAMPLES-2026-10-10.md，只是调试记录，未做上述控制变量比较。本轮未新增付费比较，不报告提升百分比。后续实际评估验收见plan/portfolio-commercial-roadmap.md。
